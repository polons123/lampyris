# Lampyris для Windows: устройство приложения

Версия для Windows (x64 и arm64) лежит в `windows/` и работает на Rust: окно на tao, страница Lampa в WebView2 (wry) и воспроизведение через libmpv. Поведение совпадает с версией для macOS ([ARCHITECTURE.md](ARCHITECTURE.md)); общие внедряемые скрипты `mpvTube.js` и `playbackCover.js` берутся прямо из `Sources/Lampyris/Resources` (включаются в exe через `include_str!`), копий нет. Сборка и CI описаны в [README](../README.md).

## Структура `windows/`
- `src/main.rs`: окно, WebView2, меню, события, состояние окна, страницы приложения; всё, что трогает WebView, живёт в главном потоке и получает работу через `EventLoopProxy<UserEvent>`.
- `src/mpv.rs`: тонкая привязка к клиентскому API libmpv. Библиотека `libmpv-2.dll` загружается во время работы (libloading), поэтому линковка не зависит от архитектуры и импорт-библиотеки не нужны.
- `src/player.rs`: порт `MpvPlayer`: создание mpv, поток событий с ограничением частоты, профили `mpv.conf` на лету, скриншот, блокировка сна.
- `src/bridge.rs`: порт `MpvBridge` (списки разрешённого, проверка источника, TheIntroDB, субтитры, «Сейчас играет»).
- `src/config.rs`, `src/log.rs`, `src/settings.rs`, `src/http.rs`: `mpv.conf`, журнал, настройки, запросы к внешним сервисам. `src/smtc.rs`: медиаклавиши. `src/pages.rs`: страницы ошибки и ввода адреса.
- `src/shim.js`, `src/window.js`: скрипты страницы, специфичные для Windows. `lampyris.manifest`, `build.rs`, `icons/icon.ico`: манифест, значок и версия exe.
- `scripts/`: `fetch-libs.ps1` (libmpv с проверкой SHA-256 из `libmpv.lock`), `build-windows.ps1` (пакет и `.zip`), `verify-bundle.ps1` (состав и архитектура), `smoke.ps1` (дымовой запуск).

Почему tao и wry, а не фреймворк Tauri: IPC Tauri рассчитан на собственные страницы приложения, а мосту нужен источник отправителя для удалённой страницы Lampa. Обработчик IPC у wry отдаёт адрес отправителя, а tao и wry — те же компоненты, на которых стоит Tauri.

## Рендеринг
mpv встраивается в главное окно через `--wid` и рисует в собственное дочернее окно класса `mpv` (на macOS так нельзя, там OpenGL-вид под страницей). WebView2 лежит над ним с прозрачным фоном, поэтому окно mpv сразу после загрузки файла опускается на дно z-порядка (`SetWindowPos(HWND_BOTTOM)`, события `file-loaded` и `video-reconfig`); при изменении размера окна mpv подстраивается сам. По умолчанию `vo=gpu-next`, `hwdec=auto-safe`; для проверки другого вывода есть `LAMPA_MPV_VO`.

## Мост страницы и mpv
- Шим `shim.js` создаёт `window.webkit.messageHandlers.mpv.postMessage({m, a})` с тем же интерфейсом, что в WKWebView (возвращает промис), поверх `window.ipc.postMessage`; ответы приходят через `window.__mpvReply`, события mpv через `window.__mpvEvent`. Шим внедряется только в главный кадр, и только если mpv запустился.
- `MpvBridge` принимает сообщения только от доверенного источника: адрес сервера и хосты редиректов при собственной загрузке (набор `trusted`, пополняется в обработчике навигации, пока идёт загрузка). Источник берётся из адреса отправителя, который передаёт wry; отличие от macOS: для вложенных кадров того же источника мост тоже доступен, а чужие кадры отклоняются по источнику.
- Списки разрешённых команд, свойств, опций открытия, схем и лимиты ответов совпадают с macOS (см. [ARCHITECTURE.md](ARCHITECTURE.md), раздел «Мост страницы и mpv»). Всё отклонённое пишется в журнал (`[mpv] … отклонено`).
- Тесты: разбор `mpv.conf` (перенесены все тесты из Swift), журнал, значения опций, источники и IMDb-идентификаторы: `cd windows && cargo test --release`.

## Окно
- **Полный экран:** WebView2 без помощи хоста раскрывал бы элемент только в границах своего окна, поэтому `window.js` подменяет `requestFullscreen`, `exitFullscreen`, `fullscreenElement` и события `fullscreenchange`; на команду приложение переключает окно (tao, без рамки) и отвечает странице `window.__setFullscreen`. Меню в полном экране скрывается.
- **Клавиши** (обрабатывает страница, меню их только подписывает): `F11` и `Alt+Enter` — полный экран, `Esc` — выход из полного экрана, `F5` и `Ctrl+R` — перезагрузка, `Ctrl+,` — адрес сервера. Клавиши плеера те же, что на macOS (справка по `H`).
- **Запоминание окна:** положение, размер (физические пиксели), «развёрнуто» и «полный экран» пишутся в `settings.json` при штатном закрытии; если сохранённое окно не попадает ни на один экран, берётся 1280×720 по центру. Размер запоминается как рабочая область без меню, но меню добавляется уже после создания окна и отнимает у неё высоту, поэтому после `menu.init_for_hwnd` высота возвращается через `SetWindowPos` (иначе каждый запуск уменьшал окно на высоту полосы меню). Наименьший размер рабочей области — 800×600 логических пикселей.
- **Один экземпляр:** переключатель «Настройки → Запретить несколько экземпляров» (`singleInstance` в `settings.json`, по умолчанию выключен, действует со следующего запуска). Процесс всегда занимает мьютекс `Local\Lampyris-single-instance`; если он уже занят и переключатель включён, процесс выводит вперёд окно первого экземпляра (оно помечено свойством окна `LampyrisMainWindow`) и завершается. В резервную копию настройка не входит.
- **Меню:** «Файл» (адрес сервера, перезагрузка, выход), «Вид» (полный экран), «Настройки» (`mpv.conf` в блокноте и проводнике, подробный журнал, папка журнала), «Справка» (о программе, строка TMDB).
- Ссылки: `window.open` и `target=_blank` на свой сервер грузятся в том же окне, на чужой открываются в браузере. Щелчок по ссылке на чужой сайт в главном окне, в отличие от macOS, не перехватывается (wry не сообщает тип навигации): такой переход только пишется в журнал `[nav]`, а мост для нового источника отключён.
- **Ошибка загрузки:** перед загрузкой приложение проверяет доступность адреса (любой HTTP-ответ годится); при отказе показывается страница с кнопками «Повторить» и «Изменить адрес сервера». Ввод адреса — страница приложения с выпадающей историей.

## Данные и файлы
- `%APPDATA%\Lampyris\`: `settings.json` (адрес сервера, история, подробный журнал, окно), `mpv.conf`. Формат `mpv.conf`, список запрещённых опций и профили те же, что на macOS; общие опции применяются при создании mpv, при каждом открытии видео файл читается заново.
- `%LOCALAPPDATA%\Lampyris\`: `Logs\lampa.log` (ротация 2 МБ × 3), `Cache\subs` (скачанные субтитры, старше недели удаляются при запуске), `WebView2` (профиль браузера: Lampa хранит там настройки).
- `%USERPROFILE%\Pictures\Lampyris`: скриншоты (`screenshot-to-file` с флагом `subtitles`, 8 бит).
- Журнал: короткие сообщения приложения пишутся всегда (файл создаётся при первом сообщении), подробные (консоль страницы, предупреждения mpv) только при включённом «Подробном журнале»; адреса http(s) сокращаются до схемы и хоста. `LAMPA_DEBUG=1` включает подробный режим и вывод в stderr (у релизной сборки консоли нет, поэтому читайте файл).

## Медиаклавиши и «Сейчас играет»
`smtc.rs` использует SystemMediaTransportControls (через `MediaPlayer` с отключённым `CommandManager`): ⏯ и пауза выполняются в mpv, перемотка и ползунок позиции тоже (кнопки вперёд и назад — ±10 с), ⏭ и ⏮ передаются странице (`window.__mpvRemote`, `Lampa.PlayerPlaylist`). Название, подпись, длительность и позиция берутся из карточки и событий mpv, постер скачивает приложение (https, до 2 МБ, проверка сигнатуры изображения, ответ предыдущего видео не заменяет постер нового).

## Обновления
`src/update.rs` повторяет логику macOS (`Update.swift` и `Updater.swift`): проверка GitHub Releases (`api.github.com/.../releases/latest`) раз в сутки и по пункту «Справка → Проверить обновления…», подписанный `SHA256SUMS.txt` (Ed25519, ключ вшит в `PUBLIC_KEY_HEX`) → SHA-256 файла. Диалог через `MessageBoxW` (Да — установить, Нет — позже, Отмена — пропустить версию), ход загрузки показывается в заголовке окна.

- Установленная копия (рядом `unins000.exe`): запускается `…-setup.exe` с `/VERYSILENT /CLOSEAPPLICATIONS /relaunch=1 /DIR=<папка> /CURRENTUSER|/ALLUSERS`. Режим берётся из записи об установке в HKCU или HKLM (для «всех пользователей» установщик сам запросит права). После установки `lampyris.iss` запускает программу заново. Журнал установщика: `%TEMP%\Lampyris-update\<версия>\setup.log`.
- Полностью портативная копия (`…-portable.zip`, рядом с exe лежит `portable.txt`): `settings::app_data_dir()` и `local_dir()` указывают в `data\Roaming` и `data\Local` рядом с exe (WebView2, журнал, кэш, настройки, mpv.conf). Обновляется своим архивом `…-portable.zip` тем же `replace.cmd`, папка `data` и `portable.txt` не трогаются.
- Резервная копия настроек (`backup.rs`, `filedialog.rs`; формат общий с `LampyrisCore/Backup.swift`): JSON `lampyris-backup` версии 1 с адресом, историей, переключателями, mpv.conf и localStorage страницы Lampa. Файл разбирается с проверкой и ограничениями размера; localStorage читается и записывается скриптом на странице только для доверенного источника, при восстановлении скрипт сверяет `location.origin`, затем страница перезагружается. Менять формат только вместе с версией Swift и тестами обеих сторон.
- Портативная копия: `.zip` распаковывается `tar.exe`, скрипт `replace.cmd` ждёт выхода приложения, меняет `Lampyris.exe` и `libmpv-2.dll` (с откатом при ошибке) и запускает новую версию. Если в папку нельзя писать, открывается страница релиза.

Настройки (`%APPDATA%\Lampyris`) и данные WebView2 (`%LOCALAPPDATA%\Lampyris`) лежат вне папки программы. Ключи `updateAutoCheck`, `updateLastCheck`, `updateSkippedVersion` хранятся в `settings.json`. Переменные для проверки те же, что на macOS (`LAMPA_UPDATE_API`, `LAMPA_UPDATE_BASE`, `LAMPA_UPDATE_PUBKEY`, `LAMPA_UPDATE_VERSION`).

## Сборка и выпуск
Пакет `Lampyris-<версия>-windows-<x64|arm64>.zip` (Lampyris.exe, libmpv-2.dll, LICENSE, THIRD-PARTY.md) собирает `windows\scripts\build-windows.ps1 -Arch x64|arm64`. Версия берётся из `scripts/VERSION` (общей с macOS), версия в `windows/Cargo.toml` обновляется вручную. libmpv: сборки mpv-winbuild (zhongfly, GPL-вариант с FFmpeg), тег, файл и SHA-256 зафиксированы в `scripts/libmpv.lock`; обновление: `fetch-libs.ps1 -Arch x64 -Update` (старые теги upstream периодически удаляет, тогда сборка не найдёт файл: обновите запись осознанно). Нужны Rust (цели `x86_64-pc-windows-msvc` и `aarch64-pc-windows-msvc`) и Visual Studio Build Tools с C++. Файлы `.ps1` хранятся в UTF-8 с BOM: Windows PowerShell 5.1 без него читает кириллицу как ANSI и не разбирает скрипт.

CI (`.github/workflows/ci.yml`): `windows-test` (`cargo test`), `windows-build` (x64 на `windows-latest`: пакет, дымовой запуск, артефакт), `windows-build-arm64` (на `windows-11-arm`; задача включена только для публичного репозитория, потому что для приватных такие раннеры недоступны, и пропускается, если репозиторий снова станет приватным), `release` по тегу `v*` публикует вместе с macOS-пакетами и общим `SHA256SUMS.txt`.

## Переменные окружения для отладки
`LAMPA_URL`, `LAMPA_ASK_SERVER=1`, `LAMPA_DEBUG` (как на macOS), `LAMPA_LIBMPV` (путь к libmpv-2.dll), `LAMPA_MPV_VO` (видеовывод mpv), `LAMPA_MPV_TEST=<файл или адрес>` с `LAMPA_MPV_PROFILE=<имя>` (окно без Lampa; при `LAMPA_DEBUG` через 5 с в журнал пишется строка `[smoke]`). Только при `LAMPA_DEBUG`: `LAMPA_EVAL=<файл.js;файл2.js>` выполняет JS на странице по очереди (результат в журнал), `LAMPA_EVAL_DELAY` — задержка в секундах.

## Известные ограничения
- Проверено на Windows 11 ARM64 в виртуальной машине (arm64-сборка и x64-сборка под эмуляцией): воспроизведение, мост, скриншот, медиаклавиши, полный экран, меню, запоминание окна. Не проверено на реальном GPU: аппаратное декодирование (`hwdec=auto-safe`), HDR и Dolby Vision, звук, `gpu-next` на разных драйверах.
- Не проверено вручную: клавиши `F11`, `Alt+Enter`, `Esc`, `F5`, `Ctrl+R`, `Ctrl+,`; восстановление полного экрана при запуске; пункты меню «О программе», `mpv.conf`, журнал; автоповтор при реальном обрыве сети; статистика торрента.
- Сборки не подписаны: SmartScreen покажет предупреждение (кнопка «Подробнее» → «Выполнить в любом случае»). Установщик (`windows/installer/lampyris.iss`, Inno Setup 6, собирается `windows/scripts/build-installer.ps1` из готового пакета) ставит приложение для текущего пользователя, добавляет ярлык и запись об удалении; настройки и журнал при удалении остаются. Если задать `LAMPYRIS_SIGN_PFX` (файл сертификата .pfx) и `LAMPYRIS_SIGN_PASSWORD`, скрипт подписывает установщик через `signtool` с меткой времени (проверено на тестовом самоподписанном сертификате; настоящий сертификат нужен, чтобы убрать предупреждение SmartScreen). Сам `Lampyris.exe` и `libmpv-2.dll` скрипт не подписывает. В CI установщик собирается для каждой архитектуры (если Inno Setup нет на раннере, скрипт с `-InstallInnoIfMissing` скачивает официальный с проверкой подписи) и попадает в релиз вместе с `.zip`.
- libmpv берётся из стороннего непрерывного релиза: закреплены тег и SHA-256, но upstream может удалить старые теги.

## Язык интерфейса
`windows/src/i18n.rs`: русский или английский, ключ `language` в `settings.json` (`ru`/`en`); без выбора берётся язык интерфейса Windows (`GetUserDefaultUILanguage`, 0x19 — русский). Тексты пишутся парой: `tr("рус", "eng")` для обычных строк и `trf!("рус {x}", "eng {x}")` для форматируемых. Пункты меню хранят обе подписи и переключаются на лету через `set_text` («Настройки → Язык / Language»), страница перезагружается (страница ошибки и ввод адреса строятся заново). Установщик (`lampyris.iss`) двуязычный и сам выбирает язык по Windows. Язык подсказок плеера внутри страницы определяет Lampa.
